# Prompt 04 — capture cost and available timing

Disposition: **implementation/native/build PASS; available read-only bench PASS;
independent electrical timing NOT RUN**. Retain the single 20-us GPTimer sampler.
Its measured capture section consumes about 20–21% of one core. No alternate
backend, slower sampler, timeout relaxation or reconstructed batch timing was added.
This is an accepted reference cost, not a production CPU-budget qualification.
Prompt 05–07 independent codec/read-only work may proceed when dispatched;
dependent physical actions remain gated below. No later prompt was executed.

## Prerequisite and implementation

Work started only after prompt 03 `b6d8535` and its fresh audit **`c1bddc3`**
were committed and synchronized with origin/main. Final commit is the commit
introducing this report. The original probe baseline was reproduced on the
audit image, SHA-256 `af531db1a18a086ddce5e1ab61c025839efff1523ef37665a72e395a5ce5979e`.
The final `bench_s3_load_timer` image is
`build/bench/prompt04_v1_timer_firmware.bin`, SHA-256
`4c55f961f3894ad57ca49e157eed1421ff1c86255d046eb9ffcc570016338001`.

`Esp32S3Uart::captureSample(bool)` now owns both task and timer sampling.
`timer_callbacks` separates alarm callbacks from aggregate `capture_samples`;
`capture_us` still measures the combined capture section. No redundant owner
or capture implementation was introduced. The BusOwner remains the sole
transaction owner; the ISR only captures UART evidence and settles DE.

Timer-mode sampling gaps reaching one conservative character minimum now latch
a capture failure even when FIFO is empty. At 115200 this is **85 us**; 84 us
passes, 85 us fails. This closes the case where starvation could hide a complete
character or disturbance. UART errors retain precedence; batch ambiguity,
FIFO/ring overflow and missing evidence still fail. Statistics reset does not
clear the fault or `sample_gap_exceeded`; explicit idle recovery does.
Starting capture establishes a sampling epoch immediately before timer start;
the first callback includes SDK startup latency and does not silently skip a gap.
Polling retains its existing interval policy and is not qualified for this load.

`capture-read [address]` adds one fixed, non-consuming FC03 read of
**0x0130/16 words**, using the existing public codec, admission, validator,
retained result and release paths. It sends `01030130001045F5` at address 1 and
expects a 37-byte normal reply or checked five-byte exception. The authoritative
function manual PDF p77 (printed p75) identifies sixteen multisegment starting
speed configuration words; p7 (printed p5) permits sixteen FC03 words. The
ledger agrees. Reads do not write, start a segment or consume a status flag.
All observed words were zero; no speed-unit/signedness interpretation is made.
This application timing fixture is not typed configuration coverage for later
prompts. It cannot choose arbitrary registers. It shares normal result capacity,
emits `capture_read` with raw frames, and never updates model/presence evidence.
Python validates address, exact request/window, reply length/count and CRC and
supports `load --capture-read`; no retries or hidden recovery were introduced.

## Selected SDK and operating restriction

Pinned platform 55.03.311 uses Arduino 3.3.11 and IDF libraries
`5.5.5+sha.b774170ff46`. The installed ESP32-S3 sdkconfig enables
`CONFIG_GPTIMER_ISR_HANDLER_IN_IRAM` and `CONFIG_GPTIMER_OBJ_CACHE_SAFE`;
`CONFIG_GPTIMER_ISR_CACHE_SAFE`, `CONFIG_GPTIMER_CTRL_FUNC_IN_IRAM` and
`CONFIG_PM_ENABLE` are unset. Actual callback/sample code is flash-resident;
`esp_timer_get_time` is IRAM-resident. Internal storage and an IRAM dispatcher
do not make the call graph cache-safe. The SDK documents deferred interrupts
while cache is unavailable without the cache-safe option: see the
[pinned GPTimer documentation](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/peripherals/gptimer.html#iram-safe).
The UART low-level TX-idle predicate checks empty FIFO and idle TX FSM, but
this source fact does not replace an electrical measurement.

**Cache-off operation while capture is running is unsupported.** `config`
exposes `cache_off_supported:false` and `sample_gap_limit_us:85`; `stats`/`load`
expose the sticky violation. Quiesce admission, settle TX/DE and idle recovery,
and stop capture before flash/OTA/NVS/cache-off or sleep operations; restart
only after normal operation returns. This standalone image has no runtime
flash/OTA/NVS/sleep service. The adapter enforces observable starvation with
a latched failure, not uninterrupted capture during an unsupported interval.
Physical cache-off/interrupt injection is **NOT RUN**; fake-SDK masking checks
the enforcement path. No claim is made that every short cache-off interval is
detectable or electrically harmless.
