## Source and ownership audit

Original function-manual physical p68 was visually rechecked (printed p66):
model/version/current-node/DIP are RO, with no consuming semantics documented.
The model default0x0305 and version0x0100 are not a mapping for observed0x4EEA
and0x0029. Scans never read alarm/event fields, issue a broadcast or reassign an
address. Register truth remains in the JSON ledger/generated descriptors.

Current FieldCore HEAD `60023936c2caf166eaf43f82254c1d9540b8522f` was inspected
read-only: Rs485Task owner/work/result queues, ShzkDeviceModule checked parsing,
ArduinoRs485Backend and current CLI conventions. Reuse the request/work/result
vocabulary and cooperative owner boundary; do not import measurement payloads,
framework ingress, retries, eight-byte TX assumptions or FC06 prefix stripping.
This application retains its single owner/UART, checked response and qualified
closure evidence. No FieldCore file was edited.

Three parallel roles covered query effects/identity, scheduling/restoration and
console/Python correlation. Root verified their concrete findings in the actual
diff. Fixes included identity progression (avoiding repeated candidates), rejected
correlation settlement, failed-host-restoration repair, deferred-stop reservation
release, common cancellation/snapshot deadlines, stale Python host-generation
provenance, identity deadline/admission-count checks and complete identity token
retention. Compact identity admission metadata preserves the8192-byte output
bound; full-width eight-finding output and backpressure are tested.

## Delivered contract and verification

[API/CLI contract](../ess_discovery.md) gives exact defaults, maximums, lifetimes,
confidence and repair policy. Each scan/query has separate correlation, copied
wire evidence, immutable tuple/target/deadline and explicit release. One scan
retains up to8 findings and four supported tuples; identity uses another request
budget entry. Urgent stop has the existing dedicated reservation and original
absolute deadline. Deferred admission never claims physical transmission or stop.
Faults stop the scan; explicit repair restores the saved tuple without resuming it.
Modbus has no wire request ID; a delayed bit-identical response remains ambiguous
and neither a host token nor finite idle gap proves uniqueness.

All63 CTest suites, generated register/version/reference checks, installed
framework-independent C++11 consumption and four firmware environments are
required and recorded in the final verification artifacts. Tests use the actual
application/owner/runner/adapter with SDK/wire fakes, not a second scan engine.
No separate UART, thread-safe ingress, generic scheduler or unbounded allocation
was added. App storage is PSRAM; capture/driver state and task stacks stay internal.
