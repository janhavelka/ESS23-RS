## Corrections and failure investigation

The old motion command runner opened separate sessions for experimental phases;
closing before restoring could lose the volatile backup. Motion now uses the
shared session owner and restores within that connection. Successful stop
requires fresh zero speed as well as non-running reports. Unknown/failed stop
does not permit a restoration write. A failed movement remains failed after
successful cleanup. The released-state action test refuses before writes so
its ending enabled state does not silently change an originally released drive.

Incomplete discovery previously could reach a terminal phase and appear to
finish despite budget exhaustion/cancellation. It now requires COMPLETE and
actual original tuple/selection, not just a restored boolean. Failed retained
result inspection/release, interrupted summary emission, absent requested work,
unavailable CPU data presented as numbers, and evidence I/O failure cannot
produce PASS. The evidence failure latch prevents a recovering file from
allowing more commands after lost evidence. Input count/interval options are
rejected for single-attempt scenarios rather than silently ignored.

Final review also found Windows text-mode CRLF expansion: early artifacts'
`evidence.bytes` counted logical LF bytes, while disk files added one byte per
record. Shared files now explicitly use LF, matching the existing probe runner.
The new real-file regression and `quick-bytefix` confirm exact byte accounting.
Historical files remain unchanged; machine-summary `actual_jsonl_bytes` records
their physical lengths. The largest archived file is484612bytes/744records;
the maximum record count is747 in a different file.

Filter failures are retained in the archive:

- `filter-01`: original2 read, candidate3 refused before TX. Fresh level reads
  were present, but the required fresh typed I/O assignment baseline was absent.
- `filter-02`: after adding that baseline,2→3 was acknowledged/read back.
  Original2 restoration was refused before TX because the accepted setting
  effect invalidated dependent caches. No failed/uncertain write was replayed.
- `filter-repair-01`: explicit known3→2 restoration also refused before TX.
  Actual caller inspection established that the first native group read detecting
  changed raw values invalidates dependent evidence again. Reading I/O first
  therefore rebuilt it too early. `filter-03` correctly refused a3→3 no-op;
  it remains a failed workload, not a repair.
- `filter-repair-02`: first read changed native group, then rebuild I/O and
  fresh stationary evidence, then one explicit original2 write. Readback PASS.
- `filter-04`: corrected normal experiment2→3→2 PASS. Restoration reads the
  group before identity/configuration/I/O/state prerequisites and verifies all
  six original raw filter values. The native regression models both invalidations.

The cause was harness prerequisite refresh/order, not transport or a weakened
firmware gate. No default, timeout, drive assignment or production API was changed.
