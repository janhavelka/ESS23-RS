# Prompt25 — Native ESP-IDF standalone consumer

Baseline `ad9a5d8`; final revision is the commit containing this report.
Only25 is implemented. Prompts01–24 retain their dispositions and named gaps;
native motion/load parity, endurance and independent electrical/shaft evidence
remain for later qualification. The secured, uncoupled ESS23-RS20 was tested
read-only on COM13. No motor setting, enable/release, motion or persistence
write was issued in this block.

## Delivered implementation

`examples/probe_idf` is a native IDF CMake application, not merely component
registration. Its example Kconfig supplies TX47/RX48/DE21, polarity and declared
receiver topology. GPIO19/20 are reserved for USB; invalid/conflicting physical
pin selections also fail the existing adapter validation. The default image
uses UART2 exclusively, 1152008N1,20-us GPTimer capture and the same portable
RTU owner, admitted validators, bounded sequences, observation/result contexts
and command inventory as Arduino.

The entire existing motor workflow moved from Arduino `main.cpp` into shared
`examples/probe_cli/ProbeApp.cpp`. Arduino now supplies a short startup/loop and
`ArduinoPlatform.cpp`; native IDF supplies `main.cpp` and `IdfPlatform.cpp`.
The example-only `ProbeApp.h`/`ProbePlatform.h` boundary exposes initialization,
bounded service, USB I/O, idle and boot diagnostics. No new installed API,
framework-dependent profile signature, second CLI, bus queue or motor workflow
was introduced. All existing common/native routes, rounding, stop, cached
status/health, reset/recover and uncertainty behavior use the same source.

The native owner runs on core 1 at priority 1 with a static 8192-byte internal
stack; the optional load fixture uses its existing 4096-byte internal worker
stack, priority 2/core 1. Initial load/delay/console output are zero. UART/capture
and fixture objects explicitly stay internal. App/results/caches/queues/traces
use one required caller-owned-lifetime PSRAM allocation; failure is reported
without a large internal fallback. UART/capture/fixture failure blocks motor
admission, retaining passive console diagnostics when App storage exists.

## Confirmed findings and fixes

1. Native compilation exposed an implicit Arduino include dependency:
   `FreeRTOS.h` must precede `task.h`. The shared source now includes both
   explicitly. Native firmware and core consumer build successfully.
2. Existing fake application tests set unknown-echo topology through a global
   before Arduino startup. Explicit startup now correctly applies the supplied
   board topology. Those fixtures explicitly initialize the alternate topology
   through `beginApplication(...,false)`; all previous uncertainty assertions
   remain, and both native configured/runtime topology cases are tested.
3. A first physical smoke received a bootloader segment-log fragment directly
   followed by the valid version JSON. Strict correlation rejected that line
   and timed out without replay. Actual SDK source identifies the exact log at
   `esp_image_format.c:646`; USB Serial/JTAG retains hardware FIFO contents,
   driver initialization preserves them, and bootloader deinitialization has
   no Serial/JTAG flush. Native defaults disable bootloader/runtime logging and
   `beginConsole` queues a checked newline before any command record. Failure
   diagnostics also lead with a newline, including ROM fallback. Queue refusal
   blocks startup before App allocation/UART setup. Native regressions retain
   the exact fragment; final physical quick passes unchanged host checks.
4. Source review found that user-selected GPIO19/20 could replace the native
   USB console with RS485. A native compile guard and Kconfig guidance exclude
   those pins. SDK guards also enforce the reviewed internal timer-object/IRAM
   handler policy and disabled runtime logging; no Arduino flags substitute
   for actual native configuration.
5. Independent evidence review caught a reporting error: the final passive
   stats sample preceded the last identity/config/state reads. Raw unique
   terminal evidence totals58 frames/594 RX bytes (quick33/319, control25/275),
   while the sampled cumulative stats show49/497. The report and structured
   artifact now count actual terminal evidence and preserve that earlier sample.

A trial optional PlatformIO-IDF launcher collided on two external `Traffic.cpp`
source basenames. It is not delivered. Genuine native CMake/Ninja handles both
paths without core file renaming or duplicated sources. Initial build logs
and failed hardware evidence are retained. An external esptool 5.3 backup attempt
first hit Windows stdout encoding, then a packet-transfer failure. The SDK's
pinned 4.12 tool completed a full read; no flash write occurred during backup.
The5.3 transfer issue is not claimed fixed or attributed to motor firmware.
