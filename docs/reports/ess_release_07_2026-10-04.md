## Production API and coverage

The installed [Axis.h](../../include/MotorControlRS/Axis.h) supplies `AxisConfig`,
`AxisReference`, `PositionRequest`, `PreparedTarget`, exact `Rational` and mixed
`NativeQuantity`, plus `configureAxis`, `setAxisOrigin`, `preparePosition`,
`parseExactNumber` and conservative `rationalToDouble`. These pure functions own
no I/O, clocks, heap, caller buffers or persistent state. Callers own complete
configurations, supplied evidence, requests and outputs; successful preparation
copies its original request and target/generation. Rejection preserves outputs
and current configuration. There is no move request or write hidden in preparation.

The [preparation contract](../axis_preparation.md) defines actual frames,
dependencies, rounding/error rules, lifetimes, host generations and CLI grammar.
`src/UnitFactors.h` shares existing spatial factor selection with `Units.cpp`;
the console parses and calls the public API rather than converting units itself.
Generated enums, descriptors, ledger and native-operation inventory are unchanged:
host arithmetic earns no device read/write/action coverage credit.

## Independent review and corrections

A numerical-boundary agent implemented/reviewed arithmetic; an API/CLI semantic
agent handled the existing console adapter. A third reviewer independently
audited integrated production code, actual callers, failure cases and original
manual pages, without authoring those paths. The lead verified findings against
source and counterexamples. Corrections made before delivery:

- Ignore unavailable optional reference evidence when no requested check needs
  it; retain strict correlation/freshness for every required reference.
- Round the final absolute target after adding origin, including negative targets
  and ties; apply host command polarity to motor/load command increments.
- Keep radian estimates separate from exact requested fractions; account for
  origin precision and starting/requested/effective endpoint limits.
- Compare exact error fractions against binary64 allowances without rounding
  uint64 operands or enlarging budgets; retain disjoint axis/unit error details.
- Latch exhausted application generation at zero across repeated invalidations,
  preventing old generation-one preparations from becoming usable. Diagnostic
  queries may expose zero; preparation and configuration reject it. Python accepts
  that diagnostic without accepting a zero-generation preparation or losing framing.

Independent integer/Fraction oracles passed **13,776 origin/rounding** and
**3,600 large-rational allowance** cases, each in normal and `-mlong-double-64`
builds. Earlier reviewer harness output is retained: one floating oracle was
incompatible with the Windows CRT long-double ABI and was replaced by integer
oracles; intentional counterexamples return the expected rejection. No production
test was weakened to conceal a failure. Final integrated reviews found no further
confirmed defect. Exact intermediates deliberately remain bounded uint64 rather
than adding arbitrary precision or silently approximating overflow.
