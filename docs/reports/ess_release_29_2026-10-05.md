Plans were written before opening COM13. On each supported physical image:

- Six read windows,100 requests each,0.2s requested spacing: model FC03 one-word
  replies and reviewed non-consuming `0x0130/16` replies at each load setting.
  Work/owner-delay/console settings are `0/0/0`, `2000/5000/128` and
  `5000/5000/256` (microseconds of worker time per10ms, owner sleep microseconds,
  output bytes per worker interval). Actual durations include console/protocol
  overhead; requested spacing is not a claim of5Hz wire throughput.
- Each window requires100 checked results, no new transport/capture/RX failures,
  firmware read duration below100ms, active-owner gap below15ms, capture gap
  strictly below85us, owner stack at least1024bytes and worker stack at least2048.
  Warmed first-three versus last-three sample median decline must be at most
 1024 internal bytes and zero PSRAM bytes. These finite samples measure observed
  trend; they do not prove long-term leak freedom.
- A600s admission budget is checked between windows/iterations/features. Already
  admitted bounded work and cleanup may finish after that budget; it is not an
  external process-kill deadline.
- After restoring unloaded operation, deliberately request20ms owner sleep for
  one stopped-state probe. Require `TX_TIMEOUT`, zero accepted TX bytes, no
  execution uncertainty, DE released and recovery required. Restore host load,
  explicitly recover, then submit a distinct read. Never replay a motor write.
- Retain eight successful probes. Require the ninth ordinary admission to return
  `results_full`; a stopped direct stop must still finish through reserved
  capacity. Inspect the original eight IDs/results before explicit release.
- Execute stopped-state normal/direct stop, release/enable; two separate finite
  relative100-native-increment moves; normal and direct stop after a new running
  report during separate finite250-increment moves. Use60rpm/configured ramps,
  retain interrupted move and stop outcomes, require checked standstill and exact
  profile restoration after every phase. Stop firmware observation interval
  must be below500ms. Prepare stop/restoration commands before moving.
- Refresh settings prerequisites, change lock delay200→201 once, verify stored
  readback and restore the saved200 once. Check the entire native control block,
  configuration, stopped feedback and ten final ordinary probes. No persistence

## Failure, cause and correction

The first Arduino aggregate run remains **FAIL**, even though all600 load reads,
the expected owner fault, retained-result pressure and all five feature phases
passed. Its final lock-delay setter was refused as `invalid`, operation ID0,
before any write was admitted. The procedure had retained identity from before
explicit recovery: identity operation43/generation1 at1279311870us versus final
control operation709/generation2 at1670652458us. It was both the wrong target
generation and about391s old.

Actual `DriverSettings.cpp` requires checked identity for the same target and
generation with age below5s. The production refusal was correct. The independent
reviewer found the same cause in the raw evidence. A dedicated stopped-state
recheck deliberately reproduced the refusal with an unchanged owner `started`
counter, then explicitly refreshed identity/configuration and completed one
typed201 write/readback and distinct200 restoration, followed by ten probes.
That separate correction run is **PASS**; it does not relabel the original run.
The matched IDF procedure includes those fresh prerequisites. No firmware or
library correction, relaxed freshness bound or automatic retry was required.

The reviewer also identified a measurement robustness issue in the local
orchestration: looking up a stop in the motion helper's32-event summary tail
could lose it during lengthy restoration polling. The corrected procedure keeps
one dedicated stop result while continuing the existing raw event stream. The
original Arduino events are present and independently analyzed from JSONL.
The600s budget is described as admission budgeting, not a hard cleanup deadline.
