## Source and architecture

The original function manual physical PDF page26 (printed24) documents save-all
`0x0042` and factory restore `0x0041` through auxiliary register `0x002D`; moving
drives ignore them. Literal node1 requests are `0106002D004299F2` and
`0106002D0041D9F3`. Appendix physical pages68/69/77 preserve distinct RW and RW/S
access. No completion flag, save duration, safe power-removal interval, flash
endurance or post-restore route is supplied. The original PDFs and ledger are
unchanged. Custom address requires save and DIP address switches OFF; baud/format
require motor power-on again, with save necessity unresolved.

Installed [`Persistence.h`](../../include/MotorControlRS/profiles/ess_rs/Persistence.h)
provides real typed preparations, one-work-token event settlement and explicit
read verification. Caller-owned state retains before identity/configuration/
stationary evidence, host tuple, raw checked frames, target/generation, accepted
TX, closure bounds and uncertainty. Fifteen standard configuration words are
retained, explicitly a partial all-parameter backup. Field access comes from
`findRegister`, preserving the ledger as the address/access source of truth.

The private `PersistenceApp.h` reuses `BusOwner::admitCommissioning` and the
existing token, runner, UART and ESS validator. Nine-read captures reuse
`prepareIdentity`, `prepareConfig` and `prepareState`; no second engine, queue,
task or unchecked write path exists. Possible save/restore transmission
invalidates host units, origins, polarity, decoding, readiness and prepared work;
historical raw contexts survive. Pending-address save retains the parent's lease
until its independently fresh candidate confirmation. Ordinary/urgent producers
cannot dispatch through an intermediate configuration. Host recovery never
replays a nonvolatile command or resolves its uncertain outcome.

Current FieldCore owner/task/backend/module/CLI were reinspected read-only;
the lead's final reference HEAD is `60023936c2caf166eaf43f82254c1d9540b8522f`.
Compatible vocabulary is request/work/result and one cooperative bus owner.
Its 8-byte TX, fixed8N1, prefix-echo handling and sensor retry workflow remain
deliberate differences: motor persistence retains source qualification and
execution uncertainty, without importing FieldCore types or retries.
