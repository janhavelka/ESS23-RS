# Implementation audit: version 0.5.1

Reviewed on 2026-10-03, starting from clean commit `d2d9a3a` (0.5.0).
The audit covers the reusable core, runner, E2 adapter, probe application,
console, Python harness, tests and their ownership/documentation contracts.
Fixes are concentrated in the example and qualification tools. The core units,
ESS register ledger and checked codecs required no change in this pass.

## Defects and fixes

| Area | Problem | Change and regression evidence |
| --- | --- | --- |
| RX silence evidence | A byte could finish after the FIFO-empty check but before the RX-idle check. The adapter could publish silence too early and clamp the next byte's start to it. | Require RX idle before and after FIFO sampling, initially empty FIFO, and no byte consumed in that snapshot. A fake publishes a byte exactly across those checks; no silence is published and the earlier start remains possible. |
| Capture/recovery | A very slow snapshot could miss a complete character. RX clear retained the old idle flag. | Reject snapshots at least one minimum character long; clear invalidates idle until a fresh sample. Native cases cover both. This still depends on the unqualified physical sampling assumptions below. |
| Terminal faults | The application waited for DE release before publishing failure or serving console commands. A stuck transmitter or failed direction cleanup could hide the terminal result indefinitely. | Publish once the runner reaches a terminal state. Continue fault cleanup while serving cached diagnostics; expose `transmit_enabled`. New traffic stays interlocked. The actual application loop is tested with TX permanently busy, then later released. |
| Fresh admission | A UART fault first discovered by the admission sample could be accepted as a new probe before failing. | Sample before the final recovery check and reject before runner admission. Native test verifies zero writes. |
| Codec evidence | The terminal line contained parse/exception details, but cached status lost them. A checked exception unnecessarily required host transport recovery. | Retain codec category, raw detail and frame error. A valid exception remains a failed probe with its rejection code, but permits another explicit request. Bad CRC still requires recovery. Actual application tests distinguish these paths. |
| Truncated evidence | The console ignored the runner's RX truncation flag when the retained prefix still fit the buffer. | Include transport truncation in `raw_truncated`; native test covers a full 64-byte retained prefix. |
| Health and replies | A capture fault before the first probe appeared as unknown communication. Synchronous host actions said accepted; `ping` used different command names for admission and completion. | Report faulted communication as failed. Host actions return `done`; probes return `accepted` and later one terminal record. `ping` uses canonical `probe` consistently. |
| Python validation | Matching IDs and `ok:true` could pass a wrong profile/address or a contradictory successful result. A terminal read crossing the deadline could pass. | Validate profile, admitted/requested/terminal address, successful FRAME/OK/model/length/timing/truncation evidence, and the deadline before success. Tests inject incorrect types, values and late delivery. A failed session never sends another command. |

The harness validates console evidence; it does not independently qualify the
UART or duplicate the firmware's Modbus codec. A device exception test uses a
synthetic valid response, not an undocumented request sent to the real motor.

## Structure and maintenance

- Kept the small public core, application-owned runner and platform adapter
  boundaries. No universal transport engine, new motion framework or placeholder
  public API was added.
- Centralized the probe application's baud/turnaround settings and derive its
  reported framing gaps from the same timing configuration used by the runner.
- Prevented accidental copying of the exclusive UART adapter. Peripheral
  exclusivity remains an application responsibility; it is not a shared driver.
- Reused one SDK fake for adapter and application tests. The application test
  compiles the real `main.cpp`, including admission, completion and `loop()`;
  it does not duplicate their implementation in a test model.
- Removed an unused include and wording that confused supported target builds
  with qualified hardware. Updated the architecture report, discovery status,
  platform review, bench guide, backlog and developer guidance.
- Preserved all nine original reference hashes and five contrasting-manufacturer
  hashes. No vendor document, register meaning or access window was changed.

## Still open

1. Independent TX/RX/DE capture must check final stop-bit, FIFO-publication,
   RX-idle detection and setup/hold bounds. The 2% duration tolerance and
   one-bit-plus-2-microsecond publication guard remain assumptions.
2. The 304-microsecond first-reply allowance is a bench exception. Host admission
   and final frame gap remain 1750 microseconds; this is not a universal ESS or
   strict high-baud Modbus timing qualification.
3. Exact connected model/firmware and configuration remain unresolved despite
   repeatable raw model `0x4EEA`. Typed identity/state reads are the next useful
   implementation block after reviewing their documented side effects.
4. Polling capture intentionally rejects multi-byte FIFO batches. Scheduler,
   USB, interrupt load, long replies, shared-bus operation and echo behavior
   need separate qualification before expanding this adapter's use.
5. Motion preparation/sequences, stop, discovery scans, full native command
   coverage, native ESP-IDF firmware and FieldCore integration remain backlog
   work. This pass issued model reads only; it performed no motion or motor
   configuration writes. A repeatable full verification command and CI also
   remain separate backlog work.

The structure is still appropriate: keep the framework-independent core small
and test the application's bus and diagnostic behavior at their real boundary.
The fixes improve that boundary; they do not establish full drive qualification.
