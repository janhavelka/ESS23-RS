# E2 read-only UART and probe qualification, 2026-10-03

The standalone path works on the connected bench: E2 UART2, TX47/RX48/DE21,
115200 8N1, node 1. A 100-probe campaign passed, followed by timeout/recovery
checks and another 20-probe campaign on the updated console build. Only the
documented model-register read was sent. No motor writes or motion occurred.

This establishes a working read-only communication path. It does **not** finish
electrical timing qualification or identify the exact motor/firmware. The console
deliberately reports `timing_qualified:false`. The current sampler depends on
explicit RX publication, baud-tolerance and idle-detection assumptions.

The bootloader/partition-table region and both application partitions were
independently verified against flash with matching digests. Whole-flash

Flash images may contain device configuration, so they stay outside Git.

The original partition map is also retained locally: NVS at `0x9000`, OTA data

The standalone example uses the same partition layout. To restore the original

The board is left running the read-only MotorControl-RS 0.5.0 probe example.
It sends nothing automatically after startup. No sibling repository was modified.

## What the drive returned

```text
TX: 01 03 00 00 00 01 84 0A
RX: 01 03 02 4E EA 0C 6B
```

The checked ESS parser accepted address, function, byte count, length and CRC.
Raw register `0x0000` is **0x4EEA (20202)**. The manual's example/default value
is `0x0305`; no supported mapping from this observed value to an exact model
has been established. Retain the raw value and responder-only confidence.
Version, alarm, readiness, encoder settings and position were not read.

The first strict test rejected the response as `EARLY_REPLY`: first-start
lower bound was 486 us after TX's latest end bound, below the standard's
recommended 1750 us high-baud frame separation. The example now explicitly
sets `Request.replyGapUs=304`, the rounded-up duration of 35 bits at 115200.
This is a bench compatibility choice based on observations, **not** a newly
discovered ESS family guarantee or a claim of strict high-baud Modbus timing.
Host admission and final frame silence remain 1750 us; inter-byte threshold
remains 750 us. No CRC, length, echo or uncertainty check was disabled.

## Measurements

The [machine-readable metrics](2026-10-03_e2_probe_metrics.json) retain campaign
counts, raw frames, hashes and before/after memory/counters. Full host JSONL
logs remain in `build/bench/`; the metrics name and hash those local artifacts.

| Measurement | 100-probe campaign | Subsequent 20-probe campaign |
| --- | ---: | ---: |
| Parsed successes | 100/100 | 20/20 |
| Transaction duration min / median / max | 5307 / 5335 / 5528 us | 5312 / 5328.5 / 5360 us |
| TX end interval width | 8-9 us | 8-9 us |
| Maximum RX interval width per reply | 18-29 us | 22-29 us |
| First-response gap lower bound | 438-649 us | 441-543 us |
| UART errors / lost captures / timeouts | 0 / 0 / 0 | 0 / 0 / 0 |

These are firmware observation bounds, not oscilloscope measurements. Duration
includes host admission and the final silent interval. The stress harness also
requested cached status, health and memory between explicit probes, with a
50 ms host pause. It was not a maximum-throughput or loaded-firmware test.
The reported maximum poll gap includes idle/console service, so it is not a
per-transaction worst-case RX service measurement.

The 128-entry trace ring wrapped as intended with an explicit overwrite count;
that is retained-history overwrite, not a UART receive overflow. No local echo
was observed on these reads using `Echo::NONE`; FC06 echo behavior is untested.

The application allocates its console, buffers, runner and trace in PSRAM once.
The small sampler and stack remain internal. Runtime free memory stayed at
344652 internal bytes and 8380332 PSRAM bytes in both campaigns. Minimum internal
free was 339504 bytes; largest internal/PSRAM blocks were 286708 / 8257524 bytes.
The final 20-probe run reported 6148 bytes of minimum-free loop-task stack.
These heap totals and static linker totals cover different memory regions.
The initial tested firmware used 23000 static RAM bytes and about 317 kB flash.

## Failure and passive-observation checks

The [captured fault-check transcript](2026-10-03_e2_fault_checks.jsonl) records:

- Invalid address and unsupported command rejected without increasing TX count.
- Address 247 produced no reply and reached the 200 ms response deadline.
- The next probe was rejected with `recovery_required`, with no automatic retry.
- Explicit host recovery after the 500 ms guard invalidated cached presence;
  a bare probe then used default address 1 and succeeded.
- Health changed from current to stale after five seconds without a new probe.
- `reset` cleared local counters while retaining the successful result.

A separate ten-iteration cached watch kept `started=101`, `frames=101` and
`rx_bytes=707` unchanged. No reset/panic evidence or changing free-memory totals
appeared in those recorded campaigns. Final review also added propagation of
idle capture faults into cached health/admission; native tests cover the latch.
That final reviewed image was uploaded successfully and passed three further
probes. Its binary hash and final smoke-log hash are recorded in the metrics.

## Qualification still required

1. External TX/RX/DE capture to check full stop-bit completion, GPIO latency,
   receive FIFO publication and RX-start/idle synchronizer behavior. The 2%
   character-duration allowance and one-bit-plus-2-us guard are assumptions.
2. Controlled malformed/gapped traffic and scheduler/USB/interrupt load on real
   hardware. Native SDK fakes cover these transitions, not electrical behavior.
3. Exact identity/firmware and selected configuration readback. Raw model alone
   does not establish manufacturer/model or readiness.
4. Native ESP-IDF firmware, longer frames, other serial tuples, shared-bus
   integration, FC06/FC10, motion, stop and persistence qualification.

The polling adapter is deliberately limited to the bench. FieldCore must retain
its existing owner and establish equivalent timing evidence under its own load.
See the [implementation guide](../esp32_probe.md) for source layout and commands.
