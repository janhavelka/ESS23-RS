## Implementation, ownership and numerical contract

`VelocityOperation.h` contains the common intent/quantity types. ESS `Velocity.h`
contains caller-owned prerequisites/context/prepared work and the common wrapper.
`src/Axis.cpp` reuses the existing exact factor cancellation, rounding and radian
interval helpers; it applies no position origin or unrelated scale requirement.
The profile stages only the reviewed three-word window, then START_SPEED.
It does not broaden paired-register writes or import another driver protocol.
Construction performs no I/O. Events borrow frames only during advance; bounded
raw evidence, accepted TX and checked closure bounds are copied and retained.

Duration starts at admission, so setup consumes it. Checked RUNNING reports are
operation activity rather than evidence of actual target RPM/acceleration.
A fresh checked stop/non-running report is required for normal success. Stop
uses the existing ActionContext and reserved urgent write; normal stop uses the
immutable pre-start deceleration snapshot described by the manual. No live
parameter changes are admitted. Failure after possible start attempts that stop
only within the original deadline, retaining primary/stop outcomes separately.
Transport recovery is explicit and cannot bypass a fault or replay start.

Local cancellation is distinct from motor stop. It settles physical TX, ends
continuations and retains needsStop/uncertainty; an explicit reserved stop can
interrupt an ordinary sequence without overwriting its original result. Uncertain
staging/trigger and needsStop preserve address conflicts across result release
and host recovery. A newly checked independent stop can reconcile the physical
conflict while historical uncertainty stays retained. New configuration/generation
invalidates unsent continuations. Same-axis reservation is separate from bus
serialization; eligible unrelated reads continue during waits.

Reference limits: eight ordinary records plus monitor and explicit-stop records;
ordinary bus pending/results4/8 and reserved urgent1/1. One UART and cooperative
owner remain. Velocity requested/effective RPM within +/-60, duration1..1000ms,
additional2s immutable stop budget, poll interval20ms/max64. These are proposed
software bounds, not a qualified physical envelope. Service later than duration
plus one poll interval records a missed stop-eligibility obligation. Urgent
pressure/faults/in-flight settlement can still prevent actual dispatch; expiry
retains unknown stop. No ESS periodic refresh or communication-loss stop is claimed.
