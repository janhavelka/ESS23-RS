## Review and corrections

A sequencing/uncertainty agent authored the core; an application/stop scheduling
agent handled the owner integration. A third reviewer inspected the original
manuals and independently reviewed core/app behavior, while implementing only
the disjoint host harness/inventory. The core author independently reviewed
console/app changes. The lead checked actual diffs, callers, failure scenarios,
manual images and the reported fixes; final reviews found no remaining confirmed
defect. Corrections made during review:

- A confirmed response source and unknown execution can coexist for a bad frame.
  Removing an over-strict envelope check preserves the actual CRC/echo error
  instead of substituting a generic transport failure. Regression covers the
  real owner-to-public-event mapping.
- Known physical targets persist across another address's successful read,
  so a priority stop does not require an unnecessary target refresh.
- Actual action TX invalidates older cached state while retaining raw evidence;
  release also invalidates host origin/reference generation. Rejected admission
  and unsent cancellation leave them intact.
- A compact uncertainty bitmap survives explicit result release, permitting a
  later stop after a failed stop/recovery without silently clearing conflict.
- Accepted interruption remains explicit when an in-flight final observation
  independently completes the previous operation.
- Stop reserves a compact admission-reply slot under USB pressure. Neither the
  original terminal nor the new stop result is overwritten.

The first full native run failed in two application variants: a new test assumed
an observation had already transmitted. GDB localized the helper assertion;
the owner had correctly cancelled that still-unsent request. The fixture now
checks actual accepted TX before deciding whether to settle a frame or harvest
cancellation. The original failure log is retained; no production guard changed.
