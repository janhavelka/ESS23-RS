## Implemented limits and APIs

Application-owned code remains under `examples/`; no framework types or clocks
enter the installed library. `Probe::Host` admits an async probe/recovery with
command ID and returns an operation ID. Completion callbacks transfer one
formatted terminal to Console; blocked output remains owned until copied by the
sink. `ResultView` borrows retained raw bytes only during synchronous formatting.
`result` is non-consuming; `release` explicitly frees a delivered terminal.
Results do not expire or overwrite unread evidence. The checked parser settles
before another owner dispatch; an exception is a device rejection, corrupt or
foreign replies interlock recovery. No automatic retries or motor writes exist.

The application has four ordinary pending slots, one active transaction, eight
ordinary reservation/retention slots, and one independent recovery result.
One urgent pending/result quota remains reserved, without a stop handler.
Nine outstanding async command correlations are bounded separately from owner
request IDs. Operation IDs never wrap within App lifetime. Python `begin`/`wait`
routes up to ten bounded command handles; `command` explicitly releases admitted
probe/recovery results after their terminal. Framing/correlation failure poisons
the host session and prevents replay or automatic recovery.

USB pressure preserves accepted/terminal output. When Console's one pending line
is blocked, the owner still services transport and bounded input; valid local
cancel runs. Other whole lines are discarded without side effects and counted
in `input_dropped`; a cancel acknowledgement can also be dropped. Its original
operation terminal remains reserved. This is an explicit bounded disposition,
not reliable delivery through a disconnected host. Load text gets one ingress
slot and only enters output while two queue slots remain; the worker never waits
for USB or calls the cooperative owner. No second command engine was added.

Absolute probe deadline is admission+500000 us; response/capture/TX budgets stay
separate and unchanged. Recovery has its own admission+2000000-us deadline;
500000-us late-traffic guard begins no earlier than physical TX/DE settlement
and explicit recovery admission. The guard cannot identify a bit-identical late
Modbus reply. Host reset preserves cached confidence and fault evidence.
