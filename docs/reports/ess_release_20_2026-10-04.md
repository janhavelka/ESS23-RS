## Implementation and source disposition

`Communication.h/.cpp` adds one caller-owned typed address/baud/format write
with checked before-provenance, candidate-specific qualification and a fixed
deadline. It reuses `ActionEvent`, `ReadTarget`, `ActiveSerialTuple` and the
existing FC06/FC03 codecs. Before/requested/readback/responding-interface
evidence remains separate. There is one write and at most two independently
armed candidate confirmation reads; no automatic follow-up or write replay.

An application commissioning lease excludes normal/urgent bus producers while
its token permits bounded session work through the existing owner. Host setup
and explicit recovery retain the lease. Failed host changes preserve candidates;
ordinary service resumes only after a settled host and a current candidate
observation, or an unsent attempt restored to its original tuple. Existing
retained results survive. Console/Python commands expose source rules before
execution and keep session outcomes inspectable under output pressure.

Original function PDF pages 6, 12, 26 and 69 and hardware PDF page 11 were
visually reviewed. Custom address requires address switches OFF and explicit
save; acknowledgement address and activation time are unspecified. Baud/format
require power-on again; their save requirement is unresolved. The old-address
write expectation is a bounded diagnostic context, never a claim that the drive
must acknowledge there. A new-address reply is not silently substituted.
No save or power control was added. Existing pending baud/format discrepancies
are rejected before new writes to avoid an unrepresented third active candidate.

## Independent review and fixes

Parallel activation/persistence-source and failure/recovery reviewers inspected
original pages and actual callers. A separate core implementer also reviewed
the application/console/Python changes it did not author; the source reviewer
independently audited the completed core/application. The lead verified their
findings against source and reproduced failures. Integration corrections:

- Preserve per-session response qualification when cache invalidation clears
  global confidence; no-write finish requires the original tuple.
- Use the reconciled endpoint for default console probes and monitoring.
- Clear confirmation eligibility on recovery and retain the admission binding
  generation so an unharvested pre-recovery reply cannot reauthorize finish.
- Require on-time, source-confirmed, non-uncertain evidence before ACK/rejection;
  ESS read-count exception 05 is not a write rejection. Accepted TX retains
  possible effects even when a checked exception reports rejection.
- Serialize immutable per-transaction budgets and reject fabricated Python
  success, foreign candidate endpoints, inconsistent states and invalid raw data.

Initial native integration also exposed missing test includes/callback hooks and
test recovery delivery without console registration. Those fixture defects were
corrected by exercising actual console admission; production release guards were
preserved. Focused failure tests were rerun before the full suite.

were inspected read-only. Its eight-byte/8N1 sensor workflow and request-prefix
