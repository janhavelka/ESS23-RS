## Source review and deliberate boundaries

The preserved original ESS function manual, physical page69, was rendered and
checked: baud codes0–3 describe115200/38400/19200/9600; format codes0–3 describe
8N1/8N2/8E1/8O1. Device settings require their documented activation treatment;
this step does not write them. Original vendor files and generated catalogue
are unchanged.

The pinned ESP-IDF5.5.5 implementation (`b774170ff46`) supplies eight data bits,
disabled/even/odd parity, one/two stop bits and `uart_get_baudrate` readback.
Actual LL TX-idle includes FIFO and transmitter state-machine settlement.
The [S3 technical reference manual](https://documentation.espressif.com/esp32-s3_technical_reference_manual_en.pdf)
v1.8 §26.3/§26.4.4 does not establish the
RX FIFO publication instant relative to the final stop bit. Consequently8N2
uses a conservative two-stop-bit residual guard; its fake publishes at the
first stop-bit midpoint while RX stays busy through the second stop, and proves
the interval contains the final physical end at all four rates. This is native
bound evidence, not an electrical observation. The provisional 2% frequency
envelope and all wire/clock assumptions remain explicit.

Current FieldCore-node `6debce7c44af9bc36f00fbcaccdfa47631846cce` RS485 task,
backend and CLI were inspected read-only. Per-request baud selection and
serialized owner vocabulary are compatible. Its Arduino UART2/8N1 adapter,
eight-byte request limit and sensor result/echo handling are deliberate
differences; no framework, product types or retry policy were imported and no
FieldCore files changed. A transient tuple does not rebind a logical endpoint.
Deliberate transport recovery retains its existing, separate generation policy.

## Fixes established during review

Two explicit-repair deadlocks were reproduced natively: buffered old RX after
timer-stop failure, and buffered RX refusing the first setup before the adapter
set its own block. Repair now discards only settled old/unknown-tuple data while
holding exclusive application ownership; physical RX/TX/DE settlement still
applies. Ordinary tuple changes still refuse buffered traffic.

Timing checks now match Runner construction budgets. Character tolerance uses
frequency division by0.98/1.02 rather than multiplying duration by1.02, which
underbounded slow characters. The8N2 guard covers both stop bits. An unavailable
startup host query returns UNAVAILABLE instead of a success-shaped unknown
snapshot.

Independent reviews reproduced Python acceptance of a mismatched failed request,
zero/out-of-envelope actual baud and a passive query falsely clearing a failed
configuration. Exact request/generation, divider and query-state checks now
reject those mutations. A failed restoration is attempted once and its unknown
state remains visible. A NO_RESPONSE read with accepted TX retains conservative
`execution_unknown=true`; the scenario checks that actual owner result rather
than fabricating known non-execution.

SDK/framing and ownership reviewers audited other authors' final integrated
source, callers and tests. Both re-reviewed the confirmed corrections and
reported no remaining concrete software defect in the inspected scope. The
lead separately inspected the diff and actual hardware evidence.
