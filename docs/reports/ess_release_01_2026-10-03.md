## Implemented production boundary

[RtuBusOwner.h](../../examples/common/RtuBusOwner.h) / `.cpp` provide
`BusOwner::admit`, `service`, `result`, `release` and explicit `recover` over
the existing Runner. `BusRequest`, `Expectation`, `Validator`, `RequestId`,
`Completion`, `PendingSlot`, `ResultSlot` and `BusStorage` are application
types outside the installed library. Construction/I/O remain separate.

Admitted frames and expectations are copied. One completion slot is reserved
before admission succeeds. Queue and result capacities are independent; no
unread terminal is overwritten. IDs check live owner/slot/generation, increment
only at reuse and never wrap. Results are non-consuming until explicit release.
All calls share one cooperative context, without thread-safe ingress or RTOS.
Service polls once, scans/compacts bounded queued work and dispatches at most once.

The synchronous validator is the completion handoff: the active reservation
remains until checked classification returns. The shipped
[ESS callback](../../examples/common/EssRtuValidator.h) uses existing profile
builders/parsers. Checked exceptions retain raw codes as `DEVICE_REJECTED`;
foreign/malformed FRAME interlocks recovery as `INVALID_REPLY`. Accepted TX
without checked settlement retains `executionUnknown`. A successful write
acknowledgement is not motion completion. No automatic replay was added.

Runner supports immutable absolute `Request::deadlineUs` and retains
`closureEarliestUs`, `closureLatestUs`, `closureQualified` without traces.
New DE assertion/enqueue stops at deadline. Setup expiry sends nothing and
releases DE. Retained physical TX/release and captured closure are processed
before task-time expiry; delayed service does not invalidate on-time closure.
The full final idle gap must fit, with straddling bounds explicitly uncertain.
Response/capture/TX/bus budgets remain distinct and are never renewed.

Recovery currently requires no active or pending request; service can expire
queued work during the interlock. Unread results survive recovery. This prevents
queued writes from implicitly resuming before 02 adds cancellation/disposition.
Caller lifetime, parser settlement and measured storage rules are in
[the owner contract](../bus_owner.md). The actual probe console remains a direct
Runner caller; replacing that path belongs to 03, after 02 scheduling.

## Source audit and deliberate FieldCore differences

Reinspected FieldCore read-only at
`ec89f52c037a1f4bd69b296505d6f96533dbca73`: `Rs485OwnerTransaction.h`,
`Rs485Task.cpp` admission/result/transport response paths,
`Rs485RuntimeIngress.h`, `Rs485Diagnostics.cpp`, `Rs485DeviceBinding.h`,
`ArduinoRs485Backend.*` and RS485 CLI workflow. Existing unrelated dirty
FieldCore work was preserved; no files there were edited, built or flashed.

Shared vocabulary is admission, queued/active/result-ready, transaction/
observation, original deadline, accepted TX and module/parser handoff. FieldCore
reserves result capacity before enqueue and releases it on exact result take.
Here result inspection is non-consuming with explicit release; ingress is
cooperative; no per-device sensor lane/framework result/health/retry types are
copied. Reviewed ESS FC10 fits without FieldCore's current eight-byte TX cap.
Explicit echo keeps FC06 acknowledgement intact. Interval/watermark closure
deliberately differs from FieldCore's untimed batches, fixed/suffix completion,
5-ms worker and deadline-before-reading-RX order. Later integration must adapt
its existing owner while preserving other sensor protocols.

Reused helpers are Runner, profile builders/parsers, callback timing and CMake
native registration. No second transport engine, scheduler framework, registry
or placeholder API was introduced. Original function PDF pp7-8 and relevant
hardware pages were rechecked; no register policy or motor semantics changed.
Vendor snapshots/generated ledger bytes are unchanged.
